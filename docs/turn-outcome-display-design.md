# 对话取消与失败展示方案（已确认）

范围：macOS 对话详情。承接已完成的工具组与上下文整理设计，本轮实现取消与失败的统一展示。iOS 在 macOS 验收后同步。

## 用户取消：本轮已取消

用户取消本轮属于正常收尾，以次级灰色单行放在本轮内容末尾、复制/分享等操作之前。不使用背景卡、边框、红色、emoji 或展开箭头，不显示 `user_requested`。不在这一行增加「重试」，用户继续操作沿用输入框。

```text
执行 3 条命令 · 读取 App.swift ›

本轮已取消

[复制] [分享] …
```

只有真实原因明确为 user_requested 时才使用「本轮已取消」文案。明确的非主动中断使用「本轮已中断」并提供有意义的原因；原因未知时使用中性文案，不猜测用户意图。内部原因码仅保存在诊断数据中。

取消不表示撤销已经执行的修改，也不表示独立后台任务已经停止。仅当本轮确有仍运行的后台任务时，可在取消行旁给出「仍有 N 个后台任务运行」的低强调提示，点击定位相应组内入口；数量以当前任务状态为准。

## 请求失败：短结论、具体原因、可用操作、技术详情

失败需要被看见，但不能把整个日志作为一大片红字铺在时间线里。使用一层轻量容器，标题和必要状态为红色，原因用正常文字，技术数据默认收起。保持与正文相同的左侧起点，不叠加大图标、红底或粗红框。

第一层显示简短的本地化错误标题，原因说明最多两三行，不直接截断原始日志来充当摘要。具体诊断内容保留在「错误详情」中。容器在本轮末尾、操作区之前出现，保留此前已经呈现的正文与工具结果，不再包一层整轮过程折叠。

截图对应的设计：

```text
上下文预算超出上限
输入内容与预留输出合计超过模型容量，本次请求未完成。

整理上下文…                错误详情 ›
```

展开详情：

```text
模型容量       1,048,576 tokens
输入占用         655,361 tokens
预留输出         393,216 tokens
合计           1,048,577 tokens
超出                   1 token

HTTP 400 · invalid_request_error

原始错误 ›                         复制错误信息
```

这一例是输入加预留输出总预算超限，不是单独的输入超过模型容量。精确差值非常小，详情必须保留整数，不能全部四舍五入成 K/M 后把超限关系抹掉。主行不显示这些长数字。

原始错误用于诊断：展开后使用等宽文本，保留完整信息、可选择和复制；高度超过上限后才在原始错误区滚动，不让整张错误卡成为嵌套滚动区域。凭证、认证头和带认证信息的 URL 必须在展示与复制前按错误字段遮盖，不能把普通 token 用量单词误判为密钥。

## 错误分类与恢复能力

- 上下文预算超限：解释输入与预留输出的关系。已有上下文整理能力可作为主要入口；调整输出预算或模型配置可作为建议，只有存在可靠的设置入口时才展示相应按钮。
- 网络连接失败、请求超时：明确终态后显示相应标题。真正可重试且重试语义已接入时才显示「重试」，不能只放一个按钮伪装已经支持恢复。
- 认证、权限、额度或速率限制：优先使用结构化错误码区分。不能仅凭 403/429 就断言密钥错误、余额不足或稍后一定恢复。
- 未识别的请求错误：使用「模型请求未被接受」或「本轮执行未完成」等中性标题，保留可展开的原始原因，不编造具体病因。

仍在自动重试时，只显示轻量的「正在重试」及服务端明确给出的次数/等待时间，不提前生成终态错误卡。失败与暂停、中断、取消需要保持不同语义，不能把用户停止产生的取消异常重新显示为失败。

上下文整理入口目前已有真实能力，但调用需满足会话空闲、连接可用等现有条件。本次默认不设计「整理并自动重试」的复合按钮；先完成整理后由用户继续发起操作，避免在没有明确重试契约时重复执行已发生的工具修改。

## 去重与状态来源

- 工具自身失败保留在工具组中，组头显示真实失败数；终态通知说明本轮为何未完成，避免重复铺出同一份完整日志。
- 同一轮次实例只有一个终态区域，按稳定的轮次身份更新；不能因重复终态事件新增多张卡。
- 用户取消用真实 reason 字段判断。当前 reducer 把 reason 拼入展示文本，正式实现应保留结构化 reason 元信息，历史 `已取消 — user_requested` 只做明确格式兼容。
- 错误类型、HTTP 状态和预算字段应由统一呈现模型提供给 Web 与原生回退。优先使用运行时结构化信息，旧日志只对已知格式保守识别；解析不全就退回通用错误，不使用零补造缺失指标。
- 真实用量未知时，页脚不显示误导的 `0.0K`。明确缺失的数据隐藏或显示「—」，已返回的真实零用量仍可显示零。

## 验收重点

用户取消后单行收尾、不出现内部码；停止与失败都不宣称独立后台任务已经终止。上下文预算的精确算式与截图一致。运行中重试不提前变为失败。错误详情收起时不占长段空间，展开可读完整信息。切换状态和重放历史不重复创建终态区域；复制诊断数据不包含明确凭证值。

正常完成不增加「已停止」或其他结束提示。「整理上下文…」打开现有上下文管理弹层，由用户主动操作；不自动压缩或重试。
