# macOS 新对话 draftView 设计方案

2026-11-17。设计基线已确认，macOS 第一版已实现；验证记录见文末。依据 `inspector-ui/对话详情/content/新对话` 中的全部 10 张参考图，并沿用已确认的 macOS Composer 规则。仅覆盖 macOS。

## 页面结构

- 顶部：沿用工作区窗口标题栏，标题为“新对话”；右侧终端、文件入口接现有面板。
- 中部：最多三个最近工作区 + 底部“选择环境”入口，构成一张轻量卡片。大面积留白，不增加欢迎标题、说明段落或推荐任务。
- 底部：已实现的统一输入框及单行环境栏，位置、最大宽度与对话详情一致。
- 有真实连接/配置错误时，在顶部工具栏下方显示可折叠诊断卡。正常状态不占位。

中间卡片以对话内容列为基准居中，不包含 sidebar 和右侧 inspector。打开/关闭侧栏、终端、文件面板后，随剩余内容列重新居中。

## 布局与外观初值

| 元素 | 设计 |
| --- | --- |
| 页面背景 | 与详情统一的语义背景；浅色近白、深色使用同一 token 的对应值 |
| 中间卡片 | 默认宽 320 pt，窄列按可用宽度减左右各 20 收缩；不随大窗口无限变宽 |
| 卡片表面 | 与页面接近的实色，1 pt 淡边框、圆角 14；常态无明显阴影 |
| 工作区行 | 高约 36 pt；左右内边距 12；文件夹图标 + 名称 + 右侧勾选 |
| 工作区名 | 字号 14，单行中间截断；同名目录增加最短可区分的父路径 |
| 环境入口 | 分隔线下约 40 pt 高，整行可点；标题“选择环境”+ 小箭头 |
| hover / 键盘焦点 | 行内柔和背景，不改变尺寸；选中状态常驻勾选 |
| 垂直位置 | 在扣除工具栏、诊断卡和底部输入框后的可用区域中，卡片中心约位于高度的 46%，略偏上 |
| 低窗口 / 长草稿 | 上下留白先收缩；剩余空间不足时仅中部滚动，输入框与环境栏始终可达 |
| 动效 | 仅轻微 hover/状态过渡，遵守减少动态效果；尺寸变化不加弹簧 |

现有 draftView 的固定 120/180 pt Spacer 改为按可用区域布局。底部输入框继续采用内容列最大 760、输入面最大 728 的现有规则，不照搬参考图的宽窗口铺满行为；窄列环境栏继续单行，不照搬终端图中的折行。

图中的像素角色属于装饰参考。优先使用本项目自己的品牌素材；没有合适素材时先保留纯卡片，不引入常驻动画。

## 工作区选择

1. 中部最多显示三个工作区；复用最近工作区存储，不改变原有完整列表容量。
2. 当前草稿的工作区必须在三个可见项中。进入页面时先确定显示顺序，在当前页面切换选中项时不立即重排行，避免选项在鼠标下跳动；下次进入再按最近使用刷新。
3. 默认选择优先级：恢复草稿自身的工作区 > 从 sidebar 工作区入口明确带入的上下文（新建空草稿）> 最近一次可用工作区。已有内容的恢复草稿不被无提示改绑。
4. 点击工作区只更新草稿上下文，不创建 session 或 Worktree，不发送消息；底部工作区入口同步更新。
5. hover 延迟显示完整路径 tooltip，键盘焦点也可查看路径；常态仅显示名称。同名目录的区分信息直接可见。
6. 切换工作区保留正文、图片和引用，复用现有引用重新校验流程。不能映射的引用明确标记，不在后台悄悄换路径。
7. 输入焦点原本在编辑器时，鼠标选择工作区后返回编辑器且保留选区；键盘操作保留正常焦点导航。
8. 首次安装无最近工作区：卡片显示“选择工作区…”行，调用现有目录选择器；仍可先编辑草稿。选好后再满足发送条件。
9. 更多工作区、选择其他目录复用底部工作区选择器，避免向三项卡片继续堆叠入口。缺失/失去授权的目录保留明确恢复入口，不自动换到另一个目录发送。

## 环境菜单

- 锚定中部“选择环境”行；底部执行环境入口复用同一个数据源和动作。
- 首版浮层显示真实的当前环境及勾选，并提供“选择或添加环境…”进入现有服务器设置；环境列表、切换确认及添加流程复用该设置页，不在 draftView 复制一套服务器管理界面。
- “添加环境…”连接现有环境配置入口；支持哪些环境由宿主真实能力决定，不因为参考图有 New environment 就伪造远程执行能力。
- 菜单优先在锚点下方，空间不足自动翻转，不能把底部输入框推走。
- 切换环境前保留草稿；重新解析该环境的工作区、模型目录及附件访问能力。不得把本机目录路径直接视作远程 runtime 上可读的路径。
- 模型继续沿用全局最近选择及现有 Effort 记忆；目标环境不可用的模型重新校验后显示真实回退结果。

## 错误状态

参考图文案泛称无法连接，但展开内容含 provider 网关地址和 probedModel。因此落地时按真实状态区分：

| 状态 | 主文案与恢复入口 |
| --- | --- |
| runtime 无法连接 | 无法连接执行环境；“打开环境设置”“重新检查” |
| 模型服务商不可达 / 认证失败 | 无法连接模型服务商 / 认证失败；“打开模型设置”“重新检查” |
| 未配置可用模型 | 尚未配置可用模型；“配置模型” |
| 首次会话 / Worktree 准备失败 | 准备任务失败，显示可执行的简短原因；“重试” |

- 默认展示图标、简短标题、原因及操作。详情默认收起；展开后用可选择的等宽文字展示脱敏诊断，提供复制入口。
- 顶部诊断卡与输入框内容边界对齐，长详情有独立高度上限；中部区域随剩余高度调整，不与底部编辑器重叠。
- 关闭仅隐藏当前错误版本的卡片，不更改连接状态；新的不同错误可以重新出现，状态未变不反复弹出。
- 重查期间只禁用检查按钮并显示局部进度，避免重复请求。恢复成功后移除卡片，不重建编辑器。
- 草稿在连接失败时仍可编辑、恢复与保存；发送是否可用由当前真实能力决定。错误不重复塞进输入框和中间卡片。
- 检查复用现有连接/模型诊断能力，不通过发送用户草稿或付费生成请求“检查连接”。

## 首条消息与性能

- 新建任务仍是本地草稿；进入页面、选工作区、打开文件面板不创建真实会话。终端操作使用既有真实的工作区终端能力，不以空消息创建会话。
- 首条消息提交沿用现有冻结模型、路径预检、附件准备和可靠提交。失败保留草稿，accepted 后迁移到对话详情并清理对应快照。
- 页面切换时输入框宽度和底部基线保持稳定；中部卡片由对话时间线接替，不做整页缩放/弹跳。
- 最近工作区来自本地存储；页面显示不递归扫描目录，不预加载会话历史，不请求模型生成欢迎内容。
- 文件可用性和环境探测复用已有状态；异步更新按环境和草稿身份丢弃过期结果。主题切换只换语义颜色，不重建 NSTextView。

## 实现边界和顺序

1. 实现 macOS 中间工作区卡片、无历史状态及响应式布局；保持 iOS 现状。
2. 接入现有工作区/环境入口、最近选择与两个新任务入口，并统一工具栏标题及面板状态。
3. 接入实际连接状态和重查动作，区分 runtime 与 provider 错误，添加折叠详情。
4. 验证 sidebar 隐藏/显示、右侧面板、低窗口、长草稿、浅/深色、恢复草稿与首条提交过渡。

主体可以复用现有 RecentWorkspacesStore、SessionDraft 和提交协议。宿主需向 AgentKit 提供可复用的环境目录/选择、连接诊断/重查/设置动作；现有 ComposerEnvironment 目前只包含名称和图标，不能据此认定完整交互已经接通。若宿主已具备能力则复用，只有缺失的能力才补接服务端，不预先新增一套 draftView API。

## 第一版实现记录

- 新增 MacDraftWorkspaceCard / MacDraftLandingView，替换 macOS 欢迎标题与固定 Spacer。普通、窄列、低窗口、首次使用及深色均有真实 NSHostingView 渲染检查。
- 中部最多三个工作区，当前选中项可见；当前页面点击只改勾选、不重排行；同名目录展示父路径；无历史记录可直接选目录。
- 环境浮层与底部入口共用 ComposerEnvironmentMenu，显示当前真实环境，选择/添加进入现有服务器设置。环境切换保护、服务端身份和工作区重建继续由已有流程负责。
- 宿主提供 runtime 连接诊断及无可用模型/缺少凭据状态。只用现有健康检查和模型目录，不发送付费模型探测请求；目录显示 available 不代表已实测提供商可达。
- 断线/认证/协议/配置问题分开提示；详情默认折叠，复制仅含允许展示的诊断字段，地址移除用户信息、query 和 fragment。周期性探测不会让同一个离线错误重复弹出。
- 首条提交失败保留草稿并引导检查后重新发送；仍沿用现有的可靠提交与迁移。iOS 不使用新布局。
- 验证：相关 30 项 Swift 测试通过，包含五项新对话专项；原生集成测试确认宽、窄、低窗口和首次使用时编辑器的底部偏移一致。macOS Direct 集成构建通过。未发送真实模型请求，未新增服务端接口。
