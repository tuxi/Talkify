# 阶段 3 · 动态布局与滚动稳定性

2026-11-18。阶段 2 已分别提交到 AgentKit `adb475a`、chater `2c322ea`。本阶段继续在相邻 AgentKit 的 macOS Web 时间线中实施；本阶段修改尚未提交。

## 复现与修正

### 同一条长回复内的阅读漂移

原有 ResizeObserver 在内容异步变高时主要维护底部跟随，历史阅读位置没有对应恢复；锚点又主要落在整个 turn。即使整轮顶部未变，轮内较早块变高也会推走正在阅读的后续段落。

用真实 WKWebView 加载同一 turn 的 32 个正文块，向上滚动至第 16 块，在第 2 块模拟异步内容增加高度。该变化不发送文档 revision，等价于延迟输出/图片布局带来的局部高度变化，但没有发送网络图片请求。

| 测量位置（逻辑 pt） | 修正前 | 修正后 |
| --- | --- | --- |
| 布局变化前，目标块顶部 | 80 | 80 |
| 上方内容变高后，目标块顶部 | 334 | 80 |
| 随后输入区 inset 增加至 240，目标块顶部 | 334 | 80 |

修正：正文块增加 turn + block 组合的稳定锚点，保留旧 turn 锚点以兼容已存视口。用户不处于手势中时，异步尺寸变化按当前模式分别处理：底部用户继续跟随，历史读者恢复块位置。只有实际偏移超过 0.5pt 才执行滚动修正，避免零偏移也触发程序滚动保护期。

### 本地展开/收起

Tasks 和长用户消息的本地操作原先没有像工具展开一样明确表达阅读意图，布局变高后可能再次触发底部跟随。

现在复用现有阅读控制器：Tasks 展开保留摘要位置；长消息展开保留消息开头，避免跳到展开内容末尾；收起保留操作位置，并受浏览器有效滚动范围约束。用户主动点击“回到最新”后恢复底部跟随。工具内部展开与其状态存储保持原实现。

### 持续按住鼠标

复现发现：原有交互结束定时器在 pointerdown 后约 160ms 就结束交互，即使鼠标仍按住。新异步布局恢复可能因此在拖选期间纠正滚动。测试中，按住 240ms 后交互被误判结束，上方增长 200pt 导致 scrollY 被纠正了 200pt。

修正：跟踪尚未释放的 pointer 和活动触摸，空闲定时器不结束仍被按住的交互。pointerup、pointercancel、touchend/touchcancel 后再结束；窗口失焦清理持有状态，避免窗口外释放导致永久锁住阅读。布局修正与文档恢复继续服从既有 interactionEpoch 检查。

## 验收项目

最终验证：TypeScript 类型检查、Vite 资源构建和 Talkify-MacDirect / Debug-MacDirect 完整 macOS 构建通过。MacConversationAppearanceTests、ConversationWebDocumentTests、MacToolGroupRenderTests、ExecutionReducerTests、TurnOutcomePresentationTests 共 **92 项通过、0 失败**。本阶段涉及文件的 diff 空白检查通过。

新增真实 WKWebView 回归：

- 同一长 turn 内异步高度增长，目标块位置保持；未发任何文档 revision。
- 历史阅读时输入区 inset 增长不拉到底部；回到最新后，继续增加 inset 能对齐新底部。
- 从底部展开 Tasks，摘要位置保持且暂停尾部跟随；可显式回到最新。
- 展开长用户消息不跳到末尾；滚动至控制处再收起，保持历史阅读模式。
- 窗口从宽视口缩至 520pt，当前可见块保持在视口顶部。
- 持续按住鼠标期间不自动结束交互，也不在其下纠正异步布局；释放和失焦后可继续使用回到最新。

继续运行既有历史分页、快速流式更新、选择、工具展开、输出懒挂载、会话视口恢复及执行状态相关回归。完整 macOS 构建用于检查生成资源与原生页面的集成。

最终一次 40 组 × 120 工具的展开基准：同步点击约 1ms，目标组 DOM 就绪约 9ms，只挂载目标 1 组，输出未提前挂载，点击位置偏移 0。该数值是单次小型基准，不作为统计性能提升结论。

## 性能和范围

追加修正：实时连接在线不等于当前轮仍在执行。底部活动提示依据当前轮执行或明确等待状态生成，避免一轮结束后残留“正在处理”；新增实际 WebView 回归，覆盖连接保持在线时结束提示消失、下一轮开始恢复，相关 64 项测试通过。正文滚动条调整为约 6pt、透明轨道和浅色滑块，悬停及拖动加深；信息栏使用系统小尺寸浮层滚动条和自动隐藏。后续 53 项信息栏与对话相关测试通过，包含真实 SwiftUI 层级中的原生滚动条检查；Web 类型检查与资源构建通过。

执行状态行采用控件整体左对齐：执行中的加载图标占用行内空间，图标左侧与正文左侧对齐，标题自然右移；执行完成移除图标后，标题回到正文左侧，不保留图标占位。工具摘要和当前状态行遵循相同规则，不使用内容区外的悬挂图标。

保持现有增量文档、DOM 复用和统一视口控制器，未引入每个块一个 ResizeObserver，也未预先挂载工具输出。正文块只是增加稳定 data-anchor-id，原有共享观察器负责恢复；没有尺寸变化或位置偏移时不额外执行滚动。

这里的数值是阅读位置偏移和现有展开基准，不能据此宣称整 App 帧率、峰值内存或输入延迟已提升。未进行 Instruments 测量，尚需用户在真实会话中体验触控板惯性、长时间拖选及图片/预览加载。

锚点粒度是稳定内容块，不是段落内部的字符。窗口重排会改变同一块内部换行；若锚点被移除或文档缩短到无法保留原偏移，恢复受实际 DOM 和滚动范围约束。未重做时间线架构、工具内部逻辑、iOS 交互或消息队列接口。工作区既有 BackgroundJobsView、ConversationDetailView 和 SessionRailView 并行改动继续保留。
