## 五态设计

统一层级：用户消息 → 执行说明/正文与既有工具过程 → 当前 Tasks → 当前活动；底部保留输入区，等待用户时在输入区上方显示已有请求组件。最终回复到来后，Tasks 保留在所属轮尾部，完成时默认收一行。预览省略完整工具内容和 sidebar，聚焦本轮要确认的区域。

| 状态 | Tasks | 当前活动 / 请求 | 输入与主操作 |
| --- | --- | --- | --- |
| 开始 | 无真实 Tasks 事件时不出现卡片；收到后才展开 | 提交确认后显示“正在处理”；没有动作事件时不编造动作或执行计划 | 保留停止；阶段 2 沿用现有运行中发送限制 |
| 进行 | 展开当前清单，标题仅 Tasks + 2/4；完成项用低强调勾，当前项用轻量运行标记，待办空心圆 | 显示一个具体当前动作；耗时仅作附属，不与已处理时长叠成多个状态行 | 输入框可见；停止入口清楚 |
| 等待用户 | 保留 2/4，可手动收起；模型数据未变就不改状态 | 将动态运行提示替换成“等待你的确认”；底部出现真实批准/拒绝组件。提问与正式 Plan 审批复用各自组件 | 普通发送沿用现有限制；不能因等待而自动发送下一条队列消息 |
| 失败 | 默认紧凑显示 Tasks 2/4，保留可展开；失败不等于所有未完成项被标成 failed | 一处简洁失败说明与可查看详情入口；仅当后端支持明确恢复语义时显示恢复操作 | 输入恢复正常；取消/失败不自动宣称完成；重试执行与普通发送有明确区别 |
| 完成 | Tasks 4/4，默认一行；用户可展开复查 | 展示最终回复；运行提示消失，时间与复制等回到既有辅助层 | 输入可用，回到发送操作 |

补充规则：

- 失败和取消不是同一结果：取消显示“已停止”，保留部分完成状态；不自动新增可重新执行工具的按钮。
- 完成轮若还有未完成 Tasks，显示实际 2/4 和“本轮已结束，仍有未完成项”，不能伪装成全完成；仍运行中的后台作业也不因 assistant 回复结束而标完成。
- 当前任务活动、排队等待资源、等待后台、等待用户、网络重连有不同原因。当前活动选择优先表达可操作请求，再表达真实执行/等待；时长不是活动证据。
- 同一轮 Tasks 稳定更新，手动展开/收起不因普通文本增长被覆盖；新消息不修改旧轮完成状态。跨轮继承只有在数据明确时才标注，不自动复制上轮 Tasks。
- 减少动态效果时用静态标记；深浅主题只换语义颜色；键盘可展开清单和访问请求操作。

## 发送语义提案与待决定项

| 动作 | 建议产品含义 | 当前结论 |
| --- | --- | --- |
| 空闲时发送 | 开始新一轮 | 沿用现有提交链路 |
| 执行中 Enter | 补充当前任务，在服务端明确的安全节点读取；不默认强杀工具 | 尚需定义 steer 或受控续轮语义与已读取事件；阶段 2 不开放 |
| 执行中 Command+Enter | 当前轮结束后按顺序开始下一轮 | 已有排队基础，但用户队列的持久呈现、边界和控制待补齐 |
| 停止 | 明确取消当前执行 | 继续核对现有 cancel 粒度；不能默认连同所有后续消息清空 |
| 排队项“立即发送” | 从 queued 原子转入“当前任务补充”路径 | 依赖补充路径确认；不能静默变成停止重开 |
| 等待审批/提问 | 当前任务暂停在需要用户决策的地方 | 不视为轮结束，不自动跳过决策消费队列 |
| 失败/取消 | 保留待处理队列，暂停自动推进并明确提示 | 建议值，需与 scheduler 当前释放策略核对；不能仅由客户端阻止显示 |
| 模型、effort 与附件 | 优先沿用已接受输入的冻结身份，权限变更单独验证 | 已见 ResolvedModel 字段与执行时 effort 处理，不能假设所有参数均已逐输入冻结 |

待确认的产品选择：本轮五态的简洁层级；进行中是否默认展开 Tasks；失败后部分 Tasks 默认收成一行；运行中 Enter 的长期目标是否采用“补充当前任务”。技术接口名称与时机在阶段 4 的契约设计中再定。

## 下一轮最小实施范围

阶段 2 只实现 Tasks 的视觉简化、状态优先级及进行/等待/结束衔接，复用既有 todo 事件、审批回调和工具摘要。不引入用户消息队列、不修改 agent loop、不重做工具内部展开、不调整 Session rail 后台作业逻辑。

实现前补齐当前活动事实来源的准确映射：若现有工具摘要已表达动作，不再附加同样内容；如果结束原因只存在终态块中，复用该结果展示而不是猜测状态。阶段 3 再验证 Tasks 折叠、审批条出现和流式增长的滚动锚点。

阶段 2 验收：五态及取消、部分完成、无 Tasks 问答、手动折叠、真实审批、历史回放；不丢失必要诊断或操作。预览只验证视觉和本地交互，不替代产品运行验收。
