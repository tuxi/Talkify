# macOS Inspector 容器规范

第二步只统一容器、导航和呈现规则；Session rail 业务内容与各工具功能留到后续阶段。

## 区域职责

```text
Workspace Header / Tool Header（同一横排，46pt）
─────────────────────────────────────────────
工具上下文：搜索、文件名或变更统计（由入口提供）
─────────────────────────────────────────────
主体：文件树 / 预览 / 差异 / 详情（各自拥有滚动区域）
```

外壳负责入口选择、面板显隐、宽度和展开。工具标题栏负责返回、标题和关闭。
入口只提供上下文操作与主体，不再增加另一条返回栏，不接管原生窗口工具栏。
Inspector 容器不在文件树、差异或预览外再加 ScrollView。

## 操作

- 返回：退回当前入口的上一层；Files/Changes 的紧凑预览返回列表，详情路径只 pop 一层。
- 返回根视图：详情路径深于一层时放在标题栏菜单中，不关闭面板。
- 关闭：收起工具并恢复之前的会话布局；不结束任务或销毁已打开的工具视图。
- 展开/还原：只切换展示空间，保持工具内容和导航状态。

Files 在实际面板宽度小于 520pt 时展示列表或预览；Changes 的分界为 620pt。
分界值由 FileViewerKit 统一提供，标题栏和内容使用相同配置。
宽面板采用并排视图，不显示无意义的列表返回按钮。

## 状态与生命周期

Inspector 使用统一的小尺寸状态视图呈现加载、初始错误及重试、空目录、无变更、
无搜索结果、未选项目和未接入入口。独立使用 FileViewerKit 的默认呈现保持可用。

首次打开工具时创建视图；同一窗口内切换或收起工具时保留已创建的视图，隐藏工具不接收
点击和无障碍焦点。列表进入预览后仍保留列表视图，返回时保留筛选、展开和滚动位置。
工作目录变更仍通过 root identity 重建 provider，避免混用不同项目的数据。

详情继续使用会话所属的 InspectorPathState 与现有目的地渲染器。macOS 自定义容器直接
呈现当前路径内容，由统一标题栏管理返回；iOS/iPad 默认继续使用 NavigationStack。
现有临时产物 selection 的创建、清理规则不在本阶段改写。

## Session rail

停靠和悬浮都复用 MacWorkspaceSessionRail。它不增加工具标题栏或外层滚动容器，
业务内容继续留空；浮层边距、圆角及外部交互关闭仍由 Workspace 外壳管理。

## 验收

- 600pt 主窗口下，右侧工具标题栏可返回、展开和关闭，没有重复返回栏。
- 进入文件或变更详情时，原生窗口工具栏不会重新出现。
- 列表和正文分别滚动，上下文操作不随正文滚走。
- 切换入口或关闭后重开，文件选择和当前筛选状态保留。
- 不创建新的对话联动入口，不实现 Terminal/Browser 功能或 Session rail 业务分组。
