# macOS 统一输入框设计方案

状态：设计基线已确认，macOS 第一版已进入实现与验证。设计日期 2026-11-16；实现进度见 [macOS 输入框实现记录](macos-composer-implementation.md)。

范围：新任务和已有对话中的同一个输入组件；先做 macOS。draftView 的标题、欢迎内容和整体排版留到下一阶段。本文数值是建议初值，单位为 macOS 逻辑 pt，需在原生实现中实测。

## 1. 设计依据与现状

已查看 `inspector-ui/对话详情/content/输入框` 的全部 13 张设计图。提取共同结构：输入区有独立圆角边框；底部环境栏在边框外；空态单行；附件在文本上方横向单排；长文本内部滚动；菜单向上展开；选中的命令与引用在正文中高亮；详情页空态可呈现下一步建议并用 Tab 接受。

文件名写 `:` 的两张图，实际内容是 `/` 命令（如 `/skills`）。本方案按用户文字及图中实际内容采用 `/`，不额外增加 `:` 触发器。

当前代码核对：

- `../AgentKit/Sources/AgentKit/Features/Conversation/Views/ConversationDetailView.swift`：`store.draft != nil` 优先进入 draftView；没有 active VM 时也回退到 draftView。draftView 内在满足空状态条件时执行 `restoreDraftOrBegin()`。
- 新任务和已有对话都使用 `DraftComposerPanel`，并非两套完全独立的输入组件。差异来自内部 `isDraft` 分支、`WorkspaceChipBar` 与父级样式。
- `MacComposerTextView` 已使用 NSTextView，已有输入法保护、Return 发送、Shift+Return 换行、高度测量；当前文本高度为 56–150。应扩展现有编辑器。
- 当前图片拖拽走附件链路，其他文件/目录直接插入路径文本。附件条隐藏横向滚动指示，现有入口最多 4 个附件。
- `SessionDraft` 和本地状态存储已有草稿 ID、工作区、worktree、模型与可靠提交基础。发送首条消息才创建真实 session；新建任务会恢复已有未发送草稿。
- 当前 `send()` 会取 `trimmed.prefix(100000)` 并提前清空文本。新方案要求超限显式提示，提交快照与正在编辑的下一条草稿分开管理。
- `UserAssetDraftCoordinator` 已有本地暂存及 `local_assets`，但也保留可选 gateway 上传。`Talkify/AppContainer.swift` 注入 picker、stager、uploader、resolver。
- `LocalUserAssetRef` 使用最终工作区相对路径、MIME、大小和摘要；不允许把外部绝对路径直接塞进这个字段。现有本地附件字段本身不能证明图片已成为模型视觉输入，需要 runtime 联调验证。

## 2. 组件结构与视觉

```text
MacComposer
  InputSurface                      唯一带边框的区域
    AttachmentStrip?                单排横向滚动，混排图片和文件
    EditorRow
      AddButton  TokenTextEditor  PrimaryAction
    InlineIssue?                    仅有真实错误时占位
  EnvironmentBar                    无独立背景、无第二层卡片
    Environment / Workspace / Worktree   …   Model / Effort / Permission / Context
  CompletionPopover?                浮层，不挤压输入框布局
```

新任务与详情中的输入框均固定在底部。新任务标题独立位于上方可滚动区域。新任务与详情采用完全一致的圆角、边框、编辑器、附件和按钮；只允许环境栏内容和容器定位随场景变化。新任务显示完整环境栏；已有对话默认仅显示右侧模型、推理强度、权限和上下文入口，工作区信息可通过同一环境栏展开查看，禁止在已有 session 上悄悄切换工作目录。

视觉：淡中性色背景、实色输入面、细边框、极轻阴影；不使用大面积模糊和双层胶囊。文字为主、图标为辅，常态无彩色状态条。焦点用细 accent 描边；附件错误局部呈现。上下文圆环是上下文使用率入口，不当作常驻加载动画。参考 Claude 实机体验后，正文引用/命令常态优先只用轻量蓝色文字；背景强调保留给选中或交互状态，避免每个引用都变成独立胶囊。

| 项目 | 建议初值 / 规则 |
| --- | --- |
| 内容最大宽度 | 与详情正文对齐：内容列外框最大 760，扣除两侧各 16 后输入面最大 728；不随长文本变宽 |
| 水平留白 | 与详情相同：外层各 20，加内容列内部各 16；宽窗口居中，窄窗口同步收缩 |
| 输入区圆角 / 边框 | 16 / 1；焦点仅换描边，不改变尺寸 |
| 空输入区 | 高 48；编辑区与两侧按钮均为 28，上下各 10；单行文字和光标在编辑区内垂直居中 |
| 正文字号 / 行高 | 14 / TextKit 自然行高（当前系统约 17）；正文、占位文字和光标使用一致布局，多行按实际内容增长 |
| 环境栏 | 高度至少 28，与输入区间隔 8；控件点击区至少 28×28 |
| 附件 | 卡片 72×96（3:4），间距 8，上下边距 12；所有类型统一尺寸 |
| 高度上限 | 整个带边框输入区不超过 min(360, 详情可用高度的 45%)；环境栏在此之外 |
| 长文本 | 上限内自然增高，达到上限后只有正文纵向滚动；附件行和主操作保持可见 |
| 低窗口 | 先缩附件至 54×72，再压缩文本可见行；极低高度可折叠附件为数量入口，至少保留两行正文 |
| 横向空间不足 | 先截断环境/工作区/模型名称，保留 tooltip；再把次要环境控件收进更多菜单，始终保持单行，窄列进一步使用图标入口和更多菜单 |

详情页底部保留实际 composer 高度对应的滚动空间，最新消息不可被遮挡。仅当时间线本来就在底部时跟随高度变化调整底部位置；用户向上阅读时保持阅读锚点。

## 3. 状态矩阵

状态应组合建模：内容（空/文本/附件/混合）×编辑（聚焦/组字/补全）×提交（可用/准备/等待确认/运行/失败），不穷举为单个巨型枚举。

| 状态 | UI | 主操作与约束 |
| --- | --- | --- |
| 空白 | 单行占位“描述任务，或输入 / 查看命令”；无附件区 | 发送禁用，无脉冲动画 |
| 聚焦 | 同尺寸，淡 accent 描边 | 焦点不带来高度跳变 |
| 短文本 | 跟随实际行数增高，操作贴编辑区底部 | Return 发送，Shift+Return 换行 |
| 长文本 | 达上限后正文内部滚动；不盖住附件和环境栏 | 不静默截断；超限显示原因和当前限制 |
| 仅附件 | 横向卡片行 + 单行编辑器 | 图片可独立发送；文件引用依赖 runtime 是否允许仅引用消息 |
| 混合附件 | 图片缩略图与文件路径卡片混排，顺序保持用户添加顺序 | 单张失败可移除/重试，其他内容不丢 |
| 拖入悬停 | 整个输入面轻微高亮并提示“添加图片或引用文件” | 真正释放后处理；拖离恢复；混合拖拽逐项报告 |
| 本地准备 | 相应卡片显示轻量进度，文本继续可编辑 | 附件未准备完不发；不显示“上传中” |
| 补全菜单 | 浮于输入框上方，默认高亮首个可用项 | Return 选项，不发消息；Esc 关闭保留输入 |
| 已选引用/命令 | 正文内淡蓝文字/极淡底色，正常行高 | 可跨越选择、复制、撤销；不是仅靠字符串着色 |
| 建议占位 | 低强调色显示建议 + 轻量 Tab 键标 | 不算正文，不激活发送；Tab 只填入，Return 后发送 |
| 提交等待确认 | 主操作显示静态等待/短时进度，防止重复发送 | 锁定提交快照；编辑新草稿不覆盖在途数据 |
| 模型运行 | 主操作变为停止，输入允许继续编辑下一条草稿 | 默认不排队、不把 Return 映射为停止；停止仅显式点击 |
| 等待审批/回答/压缩 | 环境栏附近显示简短原因及对应入口 | 保留编辑能力；是否可发服从 runtime 能力和当前阻塞原因 |
| 失败/离线 | 局部错误 + 重试，草稿保留 | 不能因网络失败重建新 session 或丢附件 |
| 归档/不可写 | 说明不可发送原因，允许选择复制 | 编辑与发送权限分别定义，不能只把整个区域灰掉 |

## 4. 附件、路径与模型多模态

### 图片

- 拖拽、粘贴截图、加号选择文件共享导入管线。立即出现占位卡，后台生成缩略图和模型输入用本地文件。
- 所有图片卡都是 3:4；预览采用 contain 保留整图，必要时中性底色补齐，避免裁掉截图文字。点击 Quick Look 看原图。
- 不展示“本地/云端”徽标。鼠标悬停或键盘焦点时出现删除按钮；右键和 VoiceOver 也能删除。删除附件能撤销，不能删除用户源文件。
- macOS 新输入框移除 OSS/gateway 上传入口、确认框及该发送分支；历史消息中的既有云资产预览保持可读，iOS 后续单独迁移，其他功能用到的 OSS 不在本次全局删除范围。
- runtime 读取最终工作区内的图片，按模型 provider 支持的多模态格式生成真正的 image content。仅发送图片路径给模型不算完成这项能力。
- 模型不支持视觉时保留草稿中的图片，发送时将其转为本地路径引用，不阻止发送；切回视觉模型后仍可发送图片内容。不能自动切模型、丢图片或转换为 OSS 上传。
- “不使用 OSS”不意味着图片不会到模型服务商；界面无需常驻隐私提示，也不能继续使用“仅本地处理”这类不准确文案。

### 非图片文件与目录

- PDF、Markdown、视频、压缩包及未知类型都作为路径引用展示；卡片用路径 + 大写扩展名（无扩展名显示 FILE，目录显示 FOLDER）。不默认做 PDF 截图或上传。
- 工作区内显示相对路径，工作区外显示 `~/…` 简写；hover/focus tooltip 展示完整路径。持久化保留真实路径及来源，不能从截断显示文本反推。
- 添加文件只建立引用，不读完整文件、不抽取全文、不转码。视频等可被引用不代表模型能直接理解其内容，实际读取由 runtime 工具及权限决定。
- 工作区内引用优先使用 workspace identity + relative path；外部引用需要持久授权或按现有本地暂存机制复制到最终工作区。客户端 bookmark 只在客户端保存，不能发给 daemon 当作可读路径。
- 不把外部绝对路径写入现有 `local_assets.relative_path`；runtime 未支持外部引用时显示“当前环境无法读取此路径”，不伪装成功。
- 同一工作区文件切到 worktree 后按最终 checkout 重解析。无法映射的引用显示未解析状态，禁止继续用旧根目录无提示发送。
- 目录不递归复制/扫描，避免拖入整个仓库卡顿。文件可读权限、符号链接解析及允许根目录由 runtime 最终校验。
- 相同来源去重但不改变其他项顺序；批量拖入中的无效项给简短汇总，不中断有效项添加。准备中的项删除后需取消后台任务，避免完成回调将其加回。

### 限制建议

图片先沿用现有处理预算：单张规范化后 ≤10 MiB，图片合计 ≤20 MiB，规范化尺寸 32–8192；最多 4 张。实际可发送数量/格式/大小取客户端硬上限与 runtime 当前模型限制的较小值。上限应来自统一配置，不能散落在 picker、drop 和 VM。

文件路径引用建议最多 16 个（含图片总卡片上限 16）。路径引用自身不沿用“文档 20 MiB 上传限制”，实际读取大小由工具能力决定；若走本地复制暂存，则需独立限制并提前展示。现有实现的 4 附件总数和常用文档白名单需要拆分为“图片导入策略”和“任意文件引用策略”。

文本先显式使用当前 100,000 字符预算，超出时保留全文并禁发，不能 `prefix` 截断；服务端若提供更低预算，则显示真实生效值。字符计数、UTF-8 字节数和 token 预算不是同一件事。

## 5. `/` 命令与 `@` 引用

共用一套浮层和键盘路由，数据源独立。命令菜单建议宽 280–360；引用菜单优先与输入区等宽，宽列时上限 640，以容纳路径和来源。菜单高不超过 320，列表可滚动；避开窗口边缘与输入法候选窗。菜单位置跟随当前编辑位置并约束在输入容器/窗口内，空间不足时翻转，不产生 layout 占位。命令说明优先放在当前行的次级文字中，避免另开一块侧向悬浮说明遮住正文。

`/` 在正文开头（允许前导空白）触发命令，后续字符过滤；正文中的 URL、普通斜杠或粘贴文本不自动触发命令。`@` 在正文开头或空白后触发；邮箱地址、代码中的普通 @ 不误弹。组字过程中不触发、不抢键。

`@` 结果按工作区内容和最近引用分组，支持文件、目录、可引用会话；只显示 runtime 已支持的类型。多工作区时显示来源副标题，重名文件用相对路径区分。选目录后可进入目录继续搜索，也可显式“引用此目录”。只取有限结果和分页，禁止客户端逐键全盘扫描。

键盘优先级：IME → 已打开的补全菜单 → 建议接受 → 编辑器默认行为。上下键移动候选，Return/Tab 接受候选；Esc 关闭；无可用候选时 Return 不误发，需先关闭菜单。左右键正常移动光标，并在离开触发范围时关闭菜单。鼠标点击候选保持编辑器焦点。

选中 `@` 项后替换触发区为 inline token，再加一个普通空格。token 有稳定 ID、类型、workspace/session identity 和真实引用；显示文字只负责展示。原生使用 NSTextStorage 属性范围或适合文本系统的原子表示；删除一个 token 为一次 undo，光标不能停在其隐藏元数据内部；中文、emoji、组合字符下使用 NSTextView 的 UTF-16 范围映射。

复制默认导出可读文本/路径；应用内复制可额外带结构化引用。从纯文本粘贴不凭相同名称重建有权限的引用。编辑显示文字前先转换为普通文本并移除引用身份，避免 UI 和 payload 不一致。

`/` 项必须有执行语义：

- insert：插入命令 token，可能继续填写参数；仅 Enter 提交时执行。
- openUI：例如模型、权限或设置，选择后打开对应界面，不作为普通消息发送。
- runtimeAction：由 runtime 描述参数、运行时是否可用及结果，按命令要求提交；需要确认的操作保留确认步骤。

截图中的 plugin/model/skills 等不是静态写死的菜单清单。客户端动作和 runtime 能力合并时按稳定 ID 去重，不能渲染服务端返回的任意 UI 或直接执行任意字符串。

请求建议防抖 120 ms，取消旧请求，响应以 draft/session + workspace + query revision 对齐，旧响应不能覆盖新查询。已缓存结果先呈现；无结果、加载、失败各有轻量行，错误不自动清除用户的 `/` 或 `@`。

## 6. 草稿、提交与下一步建议

- 一个草稿对应稳定 draft ID；已有对话按 session ID 隔离。保存正文、结构化 token、附件来源及本地文件、模型选择意图、环境/工作区、worktree、权限意图、schema version；选择范围和滚动位置可作为本地恢复信息。
- 沿用 `ConversationLocalStateStore`，键入后约 300 ms 合并保存；切换会话、失焦离开、窗口关闭前 flush。生成中的缩略图不阻塞文本保存。
- “新建任务”沿用当前恢复未发送草稿语义；从工作区新建时明确工作区来源，不能无提示把旧草稿引用改绑到新工作区。工作区变更保留文本并重新校验引用和能力。
- 发送冻结 immutable payload + request ID + draft revision；新任务创建 session 后原子迁移本地状态，worktree 创建/会话创建/首条消息之间的失败应支持原幂等身份重试。
- 本方案建议在 accepted 前保留已提交内容并只读展示；accepted 后只清除该快照，解锁下一条草稿。失败直接恢复可编辑，避免当前提前清空再按文本前缀回填的歧义。若未来采用乐观清空，需要独立 pendingSubmission 与 nextDraft，两者不得通过字符串前缀合并。
- 运行中可编辑下一条；未声明队列能力时不发送、不自动排队。明确 stop 与 send 两个意图，Return 永不隐式取消运行。
- 详情中的下一步建议由服务端在一轮结束后异步提供。仅当当前会话空正文、无附件、无 token、未组字且建议与最新 turn/revision 匹配时显示。
- 建议属于占位数据，不保存成正文。Tab 接受后成为普通可编辑文本，保留一次 undo；不会自动发送。Esc 可隐藏当前建议；键入立即隐藏。无建议时 Tab 正常进行键盘导航，不拦截。
- 建议迟到不得覆盖当前文字、恢复草稿或其他会话。生成失败就显示普通占位，不显示错误横幅、不阻塞轮次完成。

## 7. 环境栏与主题基础

新任务：左侧 This computer/实际执行环境 → 工作区选择 → Worktree；右侧模型 → 支持时显示推理强度 → 权限 → 上下文。不能固定写 This computer 来描述远程 runtime。

工作区未选也可先写草稿和添加图片，但发送需提示选择工作区；worktree 仅在 Git 与 runtime 均支持时可用，默认关闭。点击勾选不立即创建，首条提交时才创建；准备失败保留原草稿。已有会话的 checkout 固定，不能提供假 worktree 切换。

模型保留 followDefault 与 explicit 两种偏好，展示名和发送 model ID 分开。每次提交均冻结当时界面显示的有效模型并发送具体 provider/model，避免客户端目录默认值与 daemon 默认值不一致；跟随默认不写成固定的会话偏好。只展示该模型支持的 effort；切换模型后重新校验图片和参数。权限模式和作用域由 runtime 返回，不能假定 Auto 等于某个客户端枚举；当前实现权限选择会作用于工作区所有对话，菜单必须保留这个作用域说明。执行中切换的生效时机也应明确。

抽取语义 token：`composer.surface / border / borderFocused / text / placeholder / referenceText / referenceFill / hoverFill / disabled / error / shadow`，以及 spacing、radius、type、motion。浅色/深色是同一套 token 的两组值，后续主题只替换值，不复制整个组件分支。

主题改变只更新颜色和材质，不重建 NSTextView，不丢焦点、组字、撤销栈、选择与滚动。控制动效约 100–150 ms，只用于焦点、hover 和轻微状态变化；尊重减少动态效果。高度跟随文本排版，不做逐字弹簧动画。

## 8. code-agent / AgentKit 协作契约

以下是需要共同确认的能力契约，不是已经存在的接口，也不预设 HTTP 路由名。现阶段仅核对了客户端，没有读取 code-agent 服务端实现；实际已有能力需服务端复核后复用。

| 能力 | 请求上下文 / 关键返回 | 客户端依赖与降级 |
| --- | --- | --- |
| Composer capabilities | runtime/workspace/session；版本、类型支持、文本/图像/引用预算、运行中输入策略 | 缺失时保守关闭相应高级功能，保留基础文本草稿 |
| 模型能力 | 精确 model identity、输入模态、图像格式/数量/字节上限、effort、可用性及原因 | 本地选择时校验；服务端提交时复核，不能只信用户手填的模型能力 |
| 命令目录 | scope、query、revision；id、label、description、actionKind、参数 schema、enabled/reason | 本地缓存；不支持的命令不假装可用 |
| 引用搜索 | environment、workspace IDs、可选 session、query、cursor、limit；稳定 ID、kind、label、relative path、source、opaque reference | 分页、取消与 stale response 保护；仅搜索授权范围 |
| 引用解析 | reference IDs + 最终 checkout；canonical target、readability、missing/moved、权限需求 | 发送前重解析；外部路径不能依赖显示字符串 |
| 结构化输入 | text + typed references + local image refs + model/effort + request ID；accepted/rejected 与稳定错误码 | 明确 token 怎么映射至 payload；不能只发高亮后的纯字符串 |
| 图像送模型 | 本地图片验证/读取、provider 图像 content 适配；非视觉模型的图片降级为路径引用 | 无 OSS；需真实模型验证图片内容进入视觉通道 |
| 工作区/worktree | 已有创建/幂等契约及最终根目录；创建状态/失败原因 | 草稿迁移、相对引用重解析和本地图片暂存在最终路径后再发送 |
| 权限 | 模式列表、当前值、作用域、修订、生效时机 | 更新失败回滚显示值，不能只本地换标签 |
| 下一步建议 | session ID、source turn ID、history revision、suggestion ID、text、可选失效信息 | 隔离迟到事件；可选事件或读取接口，不从正文猜建议 |

建议引用最小语义形状：`id / kind / sourceIdentity / relativePath? / sessionID? / displayText`。外部引用使用受控解析身份；权限凭据不写入模型正文。协议必须定义重复引用、已删除会话、目录、越界、不可读、worktree 重定位、模型不支持图像、超限、请求冲突等错误。

会话引用需定义“最近多少轮/摘要/指定片段”的注入范围和预算；选择会话不是无限制导入全部历史。命令与引用的正式 wire schema 应在服务端落定后写入 runtime-integration 文档，客户端不私造既有 wire 字段。

## 9. 性能与验收

实现以现有 NSTextView 为基础，避免每次 SwiftUI update 都重设全文 attributedString；局部更新 token 属性，保留输入法和 undo。只有文本、有效排版宽度或字体变化才测高；流式消息刷新不重新 ensureLayout 整个输入内容。菜单查询不阻塞主线程。

缩略图用后台 ImageIO 下采样及有界缓存；不在主线程解码原图。文件元数据读取异步执行，拖入大型目录不遍历。菜单首屏最多约 30 条，长列表分页；查询取消后丢弃结果。运行中消息刷新与 composer 状态观察隔离。

性能目标是验收预算，尚未实测：标准设备键入到绘制 p95 <16 ms；拖拽完成到占位出现 <50 ms；缓存菜单出现 <50 ms；网络搜索返回后下一帧更新。用 Release + Instruments 记录设备、数据量与 p95，不能凭 SwiftUI 代码宣称达标。

验收覆盖：

1. 新任务/已有对话相同内容下边框、空态高度、附件规格、菜单行为一致。
2. 1 行、20 行、100,000 字符、超限、窄列、低窗口：操作和环境栏始终可达，长内容不遮住最新消息。
3. 中文组字 Return、emoji 前后选区、粘贴、undo/redo、token 整体删除/撤销、跨 token 选择与复制均正确。
4. 文件、目录、PDF、MP4、无扩展文件、4 张不同宽高图片、混合批量拖入、超限、损坏、权限失效和重复来源。
5. 工作区切换、worktree 创建失败重试、最终根路径改变、文件移动、菜单迟到与模型切换不串上下文。
6. 两个对话间切换、重启恢复、仅图片发送、提交超时/重连/明确拒绝、accepted 到来时无关草稿不被清空。
7. 模型确实描述到图片中的独有内容，抓发送适配层确认走 image content，整个新 composer 发送链路无 OSS 调用。
8. 深浅主题切换不重建编辑器，VoiceOver 能辨识引用/删除/发送/停止，减少动态效果下无持续动画。
