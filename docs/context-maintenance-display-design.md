# 上下文整理展示方案（macOS 已实现，待体验验收）

范围：用户已确认方案，macOS 已实施。沿用工具组的低强调、默认收起和用户控制原则，iOS 展示维持原规则。下方设计依据保留，当前交付见实施记录。

## 核心建议

将 context_edited、context_pruned、compacted 统一呈现为「上下文整理」记录。同一次整理默认只显示一行，不使用 emoji、胶囊背景、成功勾或连续堆叠的系统标签。展开后解释做了哪些步骤、处理结果及用量。

上下文整理是模型运行的维护事件，不计入命令数、文件数或工具失败数。它使用与工具组相同的字号、文字起点及相邻箭头，保持视觉一致，但使用独立语义。真实任务中断仍由现有执行错误区域表达，不重复生成两张错误卡。

## 三种操作的语言

- 清理旧工具结果：清除过期、低信号的工具结果内容。显示条数；该事件当前没有结构化 token 节省值，不推算。
- 截短旧工具输出：直接减少较早工具输出的长度，可能丢失细节。说明这是截短而非生成摘要，节省值标为估算。
- 生成历史摘要：将较早的上下文整理成摘要；保留压缩后真实用量以及是否仍超过整理阈值。

不把上下文处理描述成删除用户聊天记录，也不承诺所有历史细节都会保留。

## 状态规则

- 正在整理：只有收到明确运行生命周期事件时才显示。不能因为后续尚未出现事件就假装正在执行。
- 摘要已生成、用量待确认：不要显示 0 tokens，也不要提前声明已节省多少。
- 整理完成：默认只给一条最有意义的结果。用量已测量时可展示简短前后值；完整数字在展开详情。仅清理或仅截短也可以独立完成，不强制显示三个步骤。
- 压缩效果有限：对应 ineffective。压缩可能已节省空间，但实测用量仍高于触发压缩的阈值。主行使用琥珀色状态文字，展开解释效果和条件；避免「压缩无效」与正向节省值互相矛盾。
- 压缩失败：摘要调用/提交失败，与效果有限分开。显示本地化原因；未知用量不显示为零。是否能继续、是否自动重试、是否提供手动重试都以真实执行状态和已有能力为准。
- 若后续重试成功，同一次整理记录更新为成功，展开后仍保留尝试历史，不遗留一条独立红色失败标签。不同整理操作不互相覆盖。

正常结果使用次级灰色；效果有限为琥珀色，真实失败为红色。颜色均配文字。不强制自动展开、不弹窗、不跳滚动、不覆盖用户的展开状态。窄窗口允许次级结果换行，主标题与箭头保持可辨识。

## 分组与时间线

按可靠的整理操作 ID 归并一次整理中的清理、截短、摘要和后续用量确认，不按整个 session 或整个用户轮次任意合并。

同一次整理占一个稳定位置，原位更新状态，详情保留各阶段顺序。正文仍保留原位置；不能为了合并而移动助手正文或工具。对于没有操作身份的历史记录，先仅合并相邻的上下文事件，不跨思考、正文或其他活动猜测它们属于同一次整理。不同尝试或不同整理轮次需要可区分。

## 数值真实性

- 当前截短节省值来自字节数 / 4，是估算值，不应与压缩后的模型实际 token 用量混为一种测量。
- 截短和压缩事件可能共用同一个 beforeTokens，因此节省值不能相加。
- 只显示同一口径、同一次整理的最终前后差。没有可靠前后值时只显示操作结果或单次节省值，不拼造总量。
- 用量未确认与用量确实为零必须在协议中区分。
- 截图中 959,505 → 910,301 实际减少 49,204（约 5.1%）。ineffective 表示仍越过触发阈值，并非完全没有节省。

## 实施前的代码事实与实现条件

AgentKit 的 AgentEvent 已区分 contextEdited、contextPruned 和 compacted。ExecutionReducer 把它们拼成英文文本；cleared 的条数目前在文本内，其他 token 指标在 metadata 内。Web ContextChip 直接展示英文文本，加 emoji、胶囊和 ineffective 徽标，造成当前信息杂乱。

code-agent 的 FinalizeCompaction 用下一次模型请求的 promptTokens 确认效果，并以压缩触发阈值判断 ineffective。事件定义说明 afterTokens 为零可能表示尚未测量。当前 Swift 模型没有独立的压缩开始/失败类型，也没有稳定的整理操作身份，不能只改 CSS 就完整支持运行态、失败态和跨阶段归并。

另一个边界：上下文整理函数发生错误时可能回滚 session，但此前清理/截短事件已经发出。失败后不能仅凭这些早期事件宣称清理已最终生效。

正式实现建议补充可关联的 operationID、phase、status、measurementSource、committed/rolledBack 与结构化错误。旧记录提供保守兼容，不靠错误字符串子串判断压缩失败。不先添加没有实际后端能力支撑的「重试」按钮。

## 交付建议

先确认这套语义与视觉，再实施 macOS。交互预览包含七种示例状态，可展开详情；它是设计预览，不代表应用已接入新的生命周期协议。iOS 待 macOS 验收后同步。

## macOS 实施记录

- 新增运行时 `context_maintenance` 完整观测快照：稳定 operation_id、阶段、状态、提交标记、清理条数、估算节省、实测前后用量、摘要结果和独立错误字段。自动整理与显式压缩均发布真实阶段；显式压缩失败时也恢复原上下文，避免部分变更被当作最终结果。
- 自动重试、压缩阈值和冷却决策未改变。手动压缩/上下文恢复路径新增失败回滚，相关测试包含一个修改上下文后再报错的模拟压缩器。
- 压缩统计保存整理身份及准备步骤，下一次模型请求给出用量后更新同一记录。缺失 prompt 用量保持未知，不用 0 代表释放全部空间。
- 旧事件仍发出以兼容旧客户端和 iOS；携带 context_operation_id 的兼容事件由新版 macOS 忽略，避免与完整快照重复展示。
- macOS reducer 原位更新同一节点，晚到的用量确认不迁移到新的用户轮次。相同身份恢复后仍保留先前未成功的尝试原因（最多最近 20 次，达到上限有提示）；不同身份不擅自合并。
- 历史记录仅合并相邻的上下文事件，不跨正文或思考推测关联。旧记录缺少提交状态时明确说明，不伪造运行中或失败状态。
- Web 与原生回退均使用「上下文整理」文字折叠行，默认收起、无 emoji/胶囊。展开显示步骤、估算和确认用量，失败与效果有限分色说明。结束后收到的历史运行态会显示「整理未完成」，避免回放出现永远运行中的假状态。

### 工程验证

- 相关客户端回归 165 项、0 失败；最终完整可通过范围 **766 项，8 项条件跳过，0 失败**。仍仅排除此前工具组验收中已记录的 7 项旧基线失败。
- 运行时 agent/session/server 包测试通过；`go vet` 对应范围和 `go build ./...` 通过。一项原有 `TestRunTurnWithAssetsPreservesUserGatewayAsset` 在未修改的实际仓库中同样失败，因此保留原测试并明确排除该项，未改断言掩盖问题。
- Web 类型检查和资源构建通过。实际 WebKit 覆盖运行中、待测量、效果有限、失败、成功的原位切换，保留用户展开状态，窄窗口无横向溢出。
- 新版运行时会随 macOS Direct 应用打包。旧运行时/旧记录使用兼容展示，不凭英文错误字符串猜测完整整理生命周期。未强制重启用户当前正在运行的服务。
