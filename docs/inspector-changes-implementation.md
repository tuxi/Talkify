# Changes 第一批：审阅基础

## 本批范围

macOS 本地与内嵌 Runtime 工作区的 Changes 使用连续多文件 diff，比较范围固定为 HEAD → 工作区。无首次提交时以空版本为基线。未跟踪文件单独标识并纳入列表。分支基线、历史提交、暂存操作、提交、推送、PR 和 diff 附到对话留给后续批次。

- Session rail 的 Changes 汇总、文件行和查看全部入口进入同一个 Changes 工作台；首次读取完成后仍能定位指定文件。未安装新宿主的客户端保留原导航。
- 搜索与审阅操作复用 Workspace 的单行标题栏。搜索按文件名/路径快速跳到对应 diff；列表不会变成完整文件预览。
- 默认连续展开，可按文件或全部收起/展开，支持仅未查看与下一未查看。
- 旧/新行号、增删底色、文本选择复制与分批上下文展开。连续视图去掉重复文件头和额外的 hunk 技术标题，只有一个纵向阅读区域。
- 已查看需用户明确标记；与暂存状态分离。记录按 Runtime、仓库/工作树、HEAD 版本和具体文件内容版本隔离。同一仓库的不同对话共享进度；暂存操作而内容未变时保留记录。
- 工作区变化后提示更新，不自动替换当前快照。用户更新后，仅内容版本变化的文件失去已查看标记。折叠状态、浏览位置保留，失败时继续显示原内容。
- 文件菜单保留打开 Files、复制路径和复制差异。删除文件不能打开当前文件。
- 正确区分重命名、未跟踪、部分暂存、删除、冲突、二进制、大文件、符号链接和子模块提示。重命名显示旧路径，不能拆成两项。无文本差异的属性变化也保留明确说明。
- 非 Git 目录、仓库尚无提交、干净工作区、Git 读取失败是不同状态。当前本地实现要求工作目录为 Git 根目录；嵌套目录显示根目录提示，不投影错误的路径范围。

## 数据与性能

FileViewerKit 新增 FileReviewSnapshotProvider 与 FileReviewSession。GitWorkingTreeReviewProvider 捕获文件清单、HEAD 对象身份与工作区内容，按文件懒计算 diff，省略上下文从同一快照读取。实际 diff 使用原生 Git，避免换行和重命名的行数与 Git 不一致。

初次快照读取与差异计算在后台执行。视口变化、折叠和窗口 resize 不运行 Git。只有 Changes 可见且应用活跃时每 5 秒进行轻量状态观察；恢复可见时再检测一次。观察不会替换页面。

工作区文本捕获单文件 2 MB、每快照 24 MB；最多保留 3 个快照。超限或不支持的文件显示原因，不伪造 0 行差异。diff 展示上限 1 MB / 5000 行；会话差异缓存最多 40 个文件或约 30000 行，淘汰缓存不丢失审阅进度。上下文每次最多展开 80 行。

Git 命令禁用外部 diff 与 textconv，设置只读选项、输出上限和超时，取消任务时传播给后台读取。解析使用 NUL 分隔保留含空格、制表符等文件名。符号链接不读取外部目标。

## 平台兼容与限制

iOS 和仍使用旧 provider 初始化器的宿主继续使用原有浏览界面，公共入口向后兼容。主 macOS Changes 使用新会话接口。

远程连接尚未接入本批本地快照提供器，显示 Runtime 接入提示，不读取本机同名路径。Session rail 服务端快照与本地 Changes 仍是各自时刻的 HEAD 比较观察；后续 Runtime 统一接口时再共享同一个快照来源，不能声称当前两处数字始终同一时刻一致。

本批不实现完整语法着色、左右对比、行内字符差异、图片前后预览、冲突解决或 Git 写入能力。大文件、子模块等以真实概要/限制为主。

## 验证

- FileViewerKit：66 项测试，包含新增审阅状态、版本失效、暂存状态独立、更新提示、异步隔离、失败保护、持久化和缓存预算测试。
- AgentKit：28 项 Changes / Files 入口、Inspector 与 Session rail 相关回归。
- GitWorkingTreeReviewProvider：12 项真实 Git 仓库测试。使用生产源文件与项目测试源文件的独立 Swift Package harness 运行，不启动 Talkify 主应用。
- 原生临时示例窗口：连续 diff、360 点窄面板、已查看、修改后提示更新、仅变化文件失效、搜索跳转、全部收起及分批上下文展开。
- 完整 macOS 与 iOS Simulator 构建；用户重新运行 Talkify 后验收主 Workspace 外壳中的视觉和操作。
