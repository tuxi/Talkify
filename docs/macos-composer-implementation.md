# macOS 输入框实现记录

更新：2026-11-17。设计基线见 [输入框设计](macos-composer-design.md)，HTTP 契约见 [Composer v1](runtime-integration/macos-composer-v1.md)。

## 已落地

- 新任务输入框已移出欢迎内容的 ScrollView，固定在底部；输入框与详情正文共用 760 pt 内容列外框，扣除内部留白后边框最大宽度为 728 pt，窄窗口同步收缩。原生时间线降级视图也采用相同宽度上限。
- AgentKit 新增 `MacComposerSurface`，新任务/对话详情共用。输入面与环境栏分离，空态约 48 pt；文本区域按窗口高度约束并内部滚动。语义颜色支持原生深浅外观。
- 图片与文件单排横向展示，图片 3:4 contain 预览、后台 ImageIO 下采样及 Quick Look。低窗口先缩小附件，再折叠为数量入口；整个输入面响应拖入高亮。非图片与目录保存为路径卡片，不上传、不转码、不递归复制目录。支持文件选择、拖入和图片粘贴。
- macOS 不再提供 Gateway/OSS 上传入口；旧的未提交云附件迁回本地链路，已提交请求不改写。模型目录明确不支持视觉时将图片降级为路径引用，保留原图片以支持模型切换。
- 原生 NSTextView 补全浮层接服务端查询，支持上下键、Return/Tab、Esc、点击外部关闭、取消与旧响应过滤。选择的文件/目录/技能/对话保存为带 UTF-16 范围的 token；原子删除、撤销、中文组字保护有测试。
- 路径清单现在区分文件/目录，采用不转义斜杠的 JSON 字符串引用，仍正确处理路径内引号、反斜杠及换行。用户原始正文与引用单独保存，在接受提交后绑定到运行时轮次；macOS 历史中显示原始正文和文件卡片，本地重启可恢复。
- 引用、快照和文件路径随草稿保存并迁移到 session。提交等待确认时锁定快照；接受后只清理已提交项目。超长正文不再静默截断。
- 执行环境入口接实际运行环境名称及设置；工作区沿用现有选择器；Worktree 直接勾选；模型/推理强度与工作区权限由现有目录/服务驱动。
- 服务端新增有界补全、同工作区对话快照、最终目录路径校验、轮次建议接口。建议复用辅助模型，Tab 接受，不自动发送。
- 新增组件渲染、token 删除/撤销、IME、建议、草稿迁移、文件引用清理、旧云草稿恢复测试，以及服务端作用域、边界、预算和过期结果测试。

## 尚未覆盖的验收与边界

- 尚未以真实付费模型完成图片内容识别和建议生成验收；目前验证 provider payload 与生成器 mock、HTTP 和原生交互逻辑。
- 尚未进行 Instruments 的输入延迟、内存及流式消息并发性能采样，因此不宣称满足 p95 或帧率预算。
- 当前非图片引用和会话片段会展开进入文本提交，尚不是独立 Agent Wire reference 数据类型；当前设备的新提交通过本地轮次展示记录还原正文与文件卡片；旧消息、其他设备或缺少匹配记录时仍显示完整原文，不从文本内容猜测并删除引用段。原生降级时间线显示正文与引用标签。输入框中的 token 元数据及草稿保持结构化。
- 附件目前按图片组、路径引用组展示，混合批量导入的跨类型原始顺序尚未统一。
- HTTP 文件搜索有访问/结果上限，超出后通过缩小查询范围查找，尚未实现分页索引。远程大仓库与超长路径的实机菜单交互仍需验收。
- 只接通有实际语义的命令，未复制参考 App 的所有插件/设置/存储命令。
- macOS App Store/embedded 草稿授权未适配；iOS 与 draftView 静态布局仍按计划留到后续。

## 宿主兼容修正

当前 chater 的 Inspector 标题 switch 包含 `.uiPreviewMatrix`，但本地 AgentKit `InspectorDestination` 没有该成员，导致集成失败。已删除该无对应枚举成员的分支，保持当前实际支持的导航目标。

## 改动位置

`chater`：宿主环境注入、上面的兼容修正与文档。

`AgentKit`：Composer 视图/编辑器、补全协议 DTO 与客户端、草稿持久化、最终 Worktree 引用校验、相关测试。

`code-agent`：server Composer 路由与测试，conversation 建议生成器与测试。没有改 agent loop、旧测试断言或 iOS UI。

## 混合文件发送修正（2026-11-17）

- 修正路径预检对 headless 部署方式的误判：允许桌面 daemon 的绝对路径引用元数据校验，实际读取仍由现有权限和外部路径审批控制；沙箱越界、相对路径逃逸和符号链接逃逸保持拒绝。
- 本地图片继续使用 `local_assets`，不进入普通路径清单、不使用 OSS。新增“两张图片 + 三条普通路径”准备及 wire 编码测试；`assets` 为空在这条链路中是正常的。
- 修正图片缩略图强依赖可选 host resolver 的问题，拖入的 file URL 可以直接在后台下采样，并用于 Quick Look。
- 路径预检错误现在区分访问拒绝、目标缺失、服务端不支持与连接失败，保留草稿。
- 验证：相关 Swift 测试 39 项通过；新增服务端 profile/边界用例及 Composer race 检查通过；本地图片 provider 多模态注入专项通过，包括两张图片及三条路径同时进入请求的回归；最终 macOS 构建通过，更新后的 codeagentd 已重建并打包。尚未发送真实付费模型请求。

## 四项交互修正（2026-11-17）

- macOS 底部环境栏始终单行。窄列压缩工作区/模型标签，次要 Worktree/分支入口移入更多菜单；模型使用可控宽度的按钮和现有选择浮层，避免原生 Menu 长标签越界。
- 非视觉模型的图片发送意图保存为 `imagesAsPaths`，图片和普通文件共同进入路径清单，`assets`/`local_assets` 留空；视觉模型沿用多模态附件。切换模型不破坏原图片草稿。
- 发送的返回值仅表示已交给提交链路。编辑器清理由服务端 accepted 确认触发，并读取持久化状态中的剩余引用，避免旧文件写回，同时保留下一条草稿。
- 历史图片与文件引用使用同一个横向滚动容器，高度统一为 76 px；移除单独的本地处理说明行，说明保留在悬停文本中。

本轮新增五项回归：非视觉模型图片路径降级及切回视觉模型、发送五项目后的完整清理、接受旧提交时保留下一条草稿、360/480/728 pt 控制栏单行布局，以及 WKWebView 中两张图片和三个文件同排且可横向滚动。相关 Swift 回归 82 项通过；Web typecheck 与资源构建通过；最终 macOS Direct 集成构建通过。

## 默认模型与媒体工具链修正（2026-11-17）

- Composer onSend 不再为有明确显示模型的默认选择传 nil，使用冻结的 provider/model；UI 图片能力判断与实际请求基于同一模型。保持默认偏好及首条消息迁移语义，不静默固定为显式选择。旧的“默认发送 nil”测试按本次要求更新；显式选择回归继续通过。
- 抽帧和本地图片分析支持 Host 授权的本轮已引用外部输入，不复制视频或上传文件，输出边界仍限定在工作区。新增精确文件/目录授权、相邻路径及符号链接越界回归。
- 修正视频 count 模式在 duration 结束边界取帧的问题；同时支持 JSON integer 形式的 rate 和 max_dimension，以免参数被忽略。真实生成的视频测试验证提取两张 32×32 PNG，并让 inspect_ui_image 按返回路径读取成功。
- 本地完整 OCR/grounding 失败时保留元数据，尝试快速 OCR并明确报告部分结果；模拟 CRImageReaderError 的测试不要求操作系统准确 OCR 恢复，也不把元数据当成视觉理解。
- 服务端提示词补充视觉证据、失败调用和真实产物路径的报告约束。旧对话中声称视频已经确认某个诊断的句子，不能只凭失败记录视为验证成立。
- 验证：AgentKit 相关 65 项（1 skipped，0 failures）；ClientToolsKit 相关 34 项通过，媒体专项三项通过；Runtime 模型路由隔离与 prompt 回归通过。工具包独立验证使用 SwiftPM native 后端，避开默认后端已有 CoreML 自动生成 model.swift 名称遮蔽错误；macOS App 集成构建验证实际宿主。未重新向真实付费模型发送用户的这条消息。

## 多行正文确认后未清空修正（2026-11-17）

发送前将正文 trim 后保存到编辑器提交快照，而确认清理用原始编辑文本做相等比较。首尾空行、空格或 CRLF 导致比较失败，编辑器残留文本还会写回已清空的持久化草稿。失败恢复遇到前导空白时也可能重复插入正文。

macOS 改为保存原始编辑快照，仅在组装 wire 正文时 trim；确认后在 MainActor 同步完成清理，保留不同的下一条草稿。iOS 维持原先的快照和延后协调方式。本次不从历史消息猜测并删除已经保存、没有在途提交身份的草稿。

新增三项直接调用 send → pending → accepted/rejected 的回归，覆盖首尾空白/多行/CRLF、失败原样恢复与下一条草稿保护。先在旧实现复现失败，再验证修复：相关测试 99 项通过，macOS Direct 集成构建通过。

## 模型/Effort 菜单与最近选择恢复（2026-11-17）

- 新增 MacComposerModelPicker/MacComposerEffortPicker。模型浮层移到模型标题按钮的锚点；模型行虚拟化滚动，Effort 位于滚动区域之外，子浮层优先向左展开。当前有效模型有勾选，打开长列表时定位到已选项，支持键盘上下移动和 Return 选择。
- 复用原有 `lastSelectedModel` 持久化，修正新任务总是优先默认模型及新草稿不读取最近选择的问题。跨工作区、重启均可沿用；未完成草稿的明确选择和在途请求不被全局最近选择覆盖。
- Effort 按规范化模型身份独立保存在 UserDefaults，恢复时校验当前能力；Off 仅在模型明确允许关闭推理时出现。无历史选择使用模型默认值，范围变化时不发送失效档位。保留清除 override 的“默认”入口。
- 新增五项回归，覆盖跨工作区/重启、模型能力变化、无可用最近模型、目录延迟加载、草稿及在途保护，并在屏幕外真实 AppKit 窗口验证 30 模型列表初始滚至当前最后一项。模型与 Effort 原生组件已渲染检查。
- 相关 89 项测试全部通过，macOS Direct 集成构建通过。原先“新草稿总使用默认模型”的一处测试断言按用户最新要求调整，已有对话独立选择的断言保持。
