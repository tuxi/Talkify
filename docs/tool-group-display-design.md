# 对话详情：macOS / iOS 工具组展示方案

日期：2026-11-16。版本：v1.1（macOS 首轮验收修订）。状态：已与用户确认，作为 macOS / iOS 对话详情工具组改版的实施基线；先实施与验收 macOS，iOS 待 macOS 验收后再启动。

## 分平台交付顺序

用户已明确交付顺序：本批只实现 macOS，包括桌面 Web 主路径和桌面原生回退路径。macOS 完成工程验证后交由用户验收实际交互；验收通过且效果符合预期后，再启动 iOS 展示改造。

本批可以添加供桌面使用的数据字段和语义投影，但不切换 iOS 当前的默认展开、过程折叠、工具列表或输出布局。后续 iOS 实施沿用本文规范，并结合 macOS 验收反馈调整尺寸与触摸交互。

## 最终确认与项目定位

本方案已经用户确认采用。这次工作属于对话详情的基础交互重构，覆盖活动组织、信息层级、展开状态、滚动归属和输入/输出呈现，为后续对话详情优化提供统一基础。

以下规则作为实施与验收的固定约束，不在实现时自行退回旧行为：

1. 按连续活动分组，保留正文与独立活动边界；不因模型调用轮次分组，不把整个 session 的工具混成一组。
2. 常规工具查看只有「工具组 → 工具详情」两级展开；完成后不增加外层过程折叠，也不搬动原有正文与工具组。
3. 工具组、工具详情默认收起；用户手动选择不被流式更新、失败或完成事件覆盖。
4. 工具组无最大高度、无内部滚动、无组内自动追尾；单工具输入头部和输出分别按内容长度独立限高并滚动。
5. 普通工具不展示类型图标；保留组级运行指示、明确的异常文字、必要的变更统计与展开箭头。
6. 输入与输出分开；命令/路径等关键输入可直接理解和复制，不随输出滚走。空输出按真实执行状态呈现。
7. 按原始时序追加与更新；用户主动查看工具或输出时，不抢阅读位置。
8. 组持续时长来自可信时间事实，不累加并行工具耗时，不在历史回放时重新计时。
9. macOS Web、iOS SwiftUI 与桌面原生回退路径遵守相同的信息与状态规则，平台差异只用于适配输入方式和布局。

可在实现和真机验收中调整的参数包括：输出最大高度、工具行密度、边距、圆角、标题换行策略和轻量过渡效果。文中的 280pt / 220pt 等尺寸是初始参数，不影响上述规则已经确定的状态。时长数据若缺失，按本文规定隐藏，不通过不可靠估算满足展示。

后续实施可以分批交付，但最终验收必须覆盖完整方案；不能只调整 CSS、移除图标或删除高度限制后就认定完成。

## 目标与设计结论

让对话正文保持连续，让工具组负责概括执行过程，让每个工具负责清楚地展示输入和输出。

采用「一行组摘要 → 平铺工具行 → 输入与输出」的结构。工具组和工具详情均默认收起，只有用户主动展开。工具组自然增长、随对话页面滚动；单工具的长输入头部和长输出分别保留受限高度的独立滚动区。去掉普通工具的类型图标，保留组级运行指示、异常文字和展开箭头。

本方案依据 `inspector-ui/对话详情/工具合集展示规则/` 中的全部 8 张参考图、Claude 桌面当前页面的直接交互核对，以及当前 Talkify 和相邻 AgentKit 的实现。采用参考中的信息结构，具体高度、字体和宽度按两端实际布局确定。

## 当前实现与问题定位

实际渲染入口是 `../AgentKit/Sources/AgentKit/Features/Conversation/Views/TurnTimelineView.swift`：

- macOS 主路径：`ConversationWebWorkbenchView` → `ConversationWebDocument` → `Web/ConversationWorkbench/src/main.tsx` / `workbench.css`。Web 无法启动时才使用 `MacNativeChatTimeline`。
- iOS 主路径：`FollowingScrollView` → `TurnView` → `AgentResponseView` → `ToolCallGroupView`。
- `Views/ToolGroupView.swift` 的旧「同名工具 ×N」组件不是这次两端主路径的共同入口，不能只改它。

| 已核实的行为 | 对体验的影响 |
| --- | --- |
| `TimelineProjection` 将正文之间的工具与 thinking 按到达顺序合并，可以跨模型调用 | 分组本身已有合理基础；应保留时序，避免再按工具类型重排 |
| macOS `useActivityDisclosure` 默认收起；iOS `ToolCallGroupView` 使用 `group.isCollecting` 作为默认展开值 | 同一执行过程在两端行为不同 |
| Web 组列表 `max-height: min(320px, 45vh)`，iOS 组列表 `maxHeight: 320` | 对话滚动、工具组滚动、输出滚动形成多层同向滚动 |
| Web 命令与输出共用一个最大高度默认 144px 的滚动区 | 输出变长时，执行的命令会滚走，输入与结果难以对照 |
| iOS 工具详情整体最大高度 144pt，默认展示原始参数 JSON | 需要滚动才能理解工具做了什么，且缺少与桌面一致的语义展示 |
| 完成后，Web `splitTurnForDisplay` 和 Swift `TurnDisplaySplit` 再把过程放进整轮折叠区 | 出现「整轮过程 → 工具组 → 工具详情」三级展开；完成瞬间用户正在看的内容可能被隐藏 |
| `ToolGroup.Entry` 保留工具和 thinking 的顺序，但没有组起止时间；Web 组 `elapsed` 当前为 nil | 组时长不能直接靠视图计时或累加工具耗时补出来 |

## 分组边界

用户理解的一轮对话是「发送一次消息 → Agent 执行 → 得到回复」。一次执行里的多次模型调用，不应该变成多个用户需要理解的层级。

1. 同一用户轮次内，没有可见正文或独立活动卡打断的工具和 thinking，属于同一个连续活动组。
2. 模型调用结束、下一次模型调用开始、单个工具结束，都不切组。
3. 非空助手正文切开前后两组，正文留在时间线原位置。下一条用户消息一定切组。
4. macOS 后台运行入口及「编辑前自检」（preMutation）纳入连续活动组，与工具和 thinking 按活动顺序展示；发起后台任务的命令与任务入口去重，在发起命令原位置替换为任务入口，保持组身份稳定。真实助手正文仍是边界。图片查看、子任务委派、workflow、独立产物/计划保留专用边界。iOS 在 macOS 验收完成前沿用既有规则。
5. 保留当前投影按底层 `turnID` 变化切断活动的保护，覆盖缺少用户消息的部分历史。
6. 以当前稳定组 ID 为基础保留身份；新增工具、状态变化、首个工具完成时，组 ID 不变。
7. 一个工具也使用相同的组结构，避免第二个工具加入时突然由工具卡变为分组卡。已有独立图片活动仍保留专用呈现。
8. 并行工具按开始/到达顺序展示，原位更新结果。禁止按完成时间重排、失败置顶或运行中置顶。

示例：

```text
用户：帮我修复并验证这个问题
助手：我先检查实现和已有测试。
工具组 A：读取、搜索、命令、thinking、修改、测试
助手：定位到了一个兼容性问题，继续检查调用方。
工具组 B：读取、修改、验证
助手：最终答复
```

这里的 A 和 B 各自可能包含多次模型调用，但不把整段 session 的工具合并成一张总卡。

## 组头

组头不放大背景卡，展开时仅在下方工具列表保留一层细边框、圆角和分隔线。整行可点击，箭头紧随时长，不强行顶到最右侧。

```text
运行中收起： [运行指示] 正在运行测试              1分12秒 ›
并行中收起： [运行指示] 正在运行测试 · 另有 2 项执行中  1分12秒 ›
组内继续处理中：[运行指示] 正在处理               1分14秒 ›
完成后收起： 执行 3 条命令 · 读取 2 次文件         1分28秒 ›
带失败的完成组：执行 3 条命令 · 读取 2 次文件 · 1 项失败 1分28秒 ›
展开：      [运行指示] 执行 3 条命令 · 读取 App.swift 1分12秒 ⌄
```

- 运行中收起时，摘要优先使用当前工具的动作说明；没有说明时使用语义标题，命令可带简短预览，不拼接命令全文或流式思考原文。
- 多项并行时显示一个稳定代表操作及剩余数量：代表项仍运行就不切换，结束后选择最早仍在运行的操作，避免标题频繁跳动。
- 无工具运行但组仍在接收活动时，显示「正在思考」或「正在处理」，不把最近一次已完成工具写成仍在执行。
- 展开后和完成后均使用有意义的操作汇总，例如「执行 3 条命令 · 读取 App.swift」。不再显示泛化的「5 项操作 · 正在执行」。汇总最多三段，优先命令、修改、创建、读取等主要操作；超过三类时显示前两类，剩余合并为一次「另有 N 次工具调用」。已知目录、Git、网页、技能、委派、会话、后台任务等操作分别使用明确名称，禁止生成多个「其他」分类。全组均为未知工具时显示「调用 N 次工具」，不根据未知工具名中的 read/run 子串猜测类型。单次读取显示文件名，多次读取按调用次数显示。
- 统计单位为实际调用次数，不把读取同一路径三次写成读取三个不同文件。shell 内的多条子命令仍属于一次工具调用，不通过字符串切分虚增数量。
- 工具类别依据实际执行类型统计，例如 `run_command` 执行的 `cat` 仍计入命令调用。语义标题可以写「读取文件」，统计口径不能随标题解析而变化。
- 组级失败数始终可见，运行中出现失败也不隐藏；运行指示与失败计数同时存在，不让一次失败掩盖其余工具仍在执行的事实。
- 正常完成不显示绿色勾、成功标签或工具类型图标。状态信息靠必要的文字表达。
- 长标题优先省略，时长、异常文字和箭头保留。窄屏允许最多两行，元信息整体换行，不能挤掉失败数。

## 工具列表与工具行

展开组后是一列平铺行。取消组级 ScrollView、最大高度和组内自动追尾。列表随外部对话滚动，不再添加「展开全部工具」这样的第二层分页折叠。

每行仅包含：语义动作标题、可选变更统计、必要状态、展开箭头。macOS 工具标题在所有窗口宽度下始终单行，过长时尾部省略，箭头紧随可见标题；展开后标题仍保持简短。命令标题优先使用工具提供的动作说明，其次复用已有语义摘要；普通命令只显示短命令名及可明确识别的子命令，例如「运行 git diff」。复杂脚本不推测目的，使用短命令名兜底。完整命令只在展开的输入区显示，不再将长路径和参数重复拼入工具行标题。去掉工具类型图标、每行耗时、重复副标题和默认原始工具名。思考行采用相同的无图标布局与内边距，展开箭头紧随标题，不占据最右端。组标题的左右内边距均为 0，与正文左侧齐平；组内工具行保留卡片所需的正常内边距。单工具耗时放到展开详情的次级信息区。

```text
读取 ConversationView.swift                         ›
搜索 ToolCallGroupView                              ›
修改 ToolCallGroupView.swift              +32 −18    ›
运行单元测试                            执行中       ›
生成测试数据                            失败         ›
```

- macOS 标题通常单行，中间省略路径但保留文件名；完整内容可通过展开查看。
- iOS 标题最多两行，失败/执行中文字和箭头有独立空间。点击区域至少 44pt，支持 Dynamic Type。
- 状态变化不改变行身份，不挪动位置。无输出的运行工具仍有工具行和正在执行状态。
- 支持同时展开多个工具，便于对照命令与结果；不要使用只能打开一项的手风琴。
- 组内 thinking 继续留在原始位置，以低强调的「思考」行呈现，默认收起；不算入工具数量，不拼进工具标题。保留既有思考详情能力。

### 重复等待工具

当前 Web 会将相邻、同一显式 job_id 的 `job_wait` 再分组，这会增加展开层级。

建议呈现为一条「等待后台任务 · 检查 8 次」的工具行，其展开内容直接显示任务、等待结果和累计状态；各次调用的参数与结果可在原始记录中查看。不再生成一张「等待组 → 每次等待工具」的嵌套列表。只压缩相邻且确认为同一任务的等待；保留原始调用记录和错误，不越过正文、thinking、其他工具或组边界合并。iOS 与 macOS 使用同一语义投影。

## 工具展开：先说明输入，再给出输出

工具行展开后，详情直接长在这一行下面，背景延续列表，不额外包一张大卡。

```text
运行单元测试                              失败 ⌄

  $ swift test --filter ToolPresentationTests     [复制命令]
  ──────────────────────────────────────────────────────
  Test Suite started...
  Assertion failed: ...
  ...                       ← 仅此长输出区可纵向滚动

  退出码 1 · 2.3秒                [复制输出] [查看完整输出]
```

输入展示按工具类型确定：

| 工具 | 首要输入 | 输出 |
| --- | --- | --- |
| shell / terminal | `$` 加命令；工作目录等影响执行含义的参数放次级行 | 等宽原文，保留换行 |
| read | 完整路径、实际读取范围；路径可复制 | 读取到的文本/代码，存在可靠行号时显示行号 |
| search | 查询词及搜索范围 | 匹配项、路径和行号；保留已有跳转能力 |
| edit / write | 文件路径及变更统计 | 已有 diff/变更结果，必要时进入 Inspector 查看 |
| MCP / 未识别工具 | 可读名称和关键参数；没有可靠语义时展示原始工具名与格式化参数 | 文本、结构化结果或现有专用呈现 |

读取路径、查询词或命令直接放在输入头部。普通工具卡内不再显示「原始详情」或原始参数 JSON 的额外展开区域；既有完整输出/Inspector 入口继续保留。后台等待的各次结果可通过完整输出入口访问，不在卡内另建原始记录区。

复制命令不包含视觉用的 `$`。命令和输出分别复制。macOS 命令仅对明确凭证位置局部遮盖，并显示「敏感值已隐藏」；普通源码关键词、文件名、非敏感环境变量与变量引用正常显示，不再整条替换成隐藏提示。复制命令使用相同的遮盖后文本，原始执行记录保持不变。iOS 暂时沿用既有规则。展开命令不因长度被截为若干行或固定字符预览。超长命令在独立输入滚动区阅读和复制，敏感参数检查覆盖完整命令。

#### macOS 后台任务入口

后台任务以组内单行入口展示，例如「运行 swift test · 后台」，与普通工具行对齐，去掉类型图标和行内总耗时。运行、失败、取消、不可用保留明确状态文字，正常完成不再增加成功标签。点击仍打开原有任务 Inspector，查看命令、完整输出与任务控制；父时间线不重复挂载日志和结果。

组摘要将后台命令计入命令次数，发起命令不重复计数；失败加入组级失败数，取消不作为失败。组内仍有后台任务运行时，组保持运行状态，即便模型轮次已经结束或某次等待已经返回。分组收起与展开均保留用户选择，任务启动和结束不强制展开，也不创建额外嵌套组。

## 命令与输出的高度

- 输入头部按实际内容自然增长；达到 160pt 或视口高度 30% 的上限后独立滚动，不与输出共用滚动区。复制命令入口留在输入滚动区外，始终可见。
- 巨型命令、heredoc、内嵌脚本保留完整展示内容，达到头部上限后滚动阅读；取消此前“约 6 行预览”的方案。短命令保持自然高度，不强行撑满或显示滚动条。
- 短输出按实际内容高度显示；长输出达到上限后才滚动。
- 初始输出上限建议 macOS 280pt、iOS 220pt，并不超过可用对话高度约 40%。这是首轮调参值，需真机验证后确定；大字号至少保证若干完整可读行。
- 输出区使用等宽字体、可选择文本和可发现的滚动条。长行默认软换行；完整视图可提供原始行布局。
- 输出末尾提供「查看完整输出」：macOS 优先复用 Inspector，iOS 使用工具详情 sheet/全屏视图。打开的是当前这一条工具记录，保留实时状态。
- 删除工具组滚动后，对话页面与长输出仍然存在两层滚动，这是控制日志长度的主动取舍。输出到边界的手势交接、惯性与文字选择必须在两端实测，不假设 CSS 或 SwiftUI 默认行为完全一致。

### 空输出状态

| 工具状态 | 实际输出为空时 |
| --- | --- |
| 执行中 | 不渲染空输出框；仅展示输入和「执行中」 |
| 成功完成，且无其他有效结构化结果 | 显示一行次级文案「无输出」 |
| 失败 | 显示真实错误；没有错误内容则显示「执行失败，未返回输出」及已知退出码 |
| 中断/取消，且事件能确认此状态 | 显示「已中断」或「已取消」；不伪装为成功无输出 |

diff、图片、产物、DAG 等有效结构化结果不属于「无输出」。当前 `ToolNodeStatus` 只有 running/completed/failed/autoApproved，不能仅为显示效果推断一个不存在的取消状态；需确认真实事件映射，必要时另补模型。

## 展开状态与阅读位置

1. 新组默认收起，新工具详情默认收起，执行中、失败和完成均不触发自动展开。
2. 手动展开组后，新工具只追加到组尾，不自动展开工具，也不自动滚动到新工具。
3. 用户手动打开的工具在完成时仍然打开，手动收起的组不会因任何流式更新再次打开。
4. 收起组后保留各工具的展开状态，再次打开恢复；按 conversationID、turnID、groupID/callID 隔离本次访问的状态，避免不同会话复用 callID 时串状态。
5. 重新进入会话默认紧凑展示；如未来需要跨访问恢复，应独立设计，不依赖当前视图偶然驻留。
6. 展开/收起时锚定用户操作的组头/工具行，保持其屏幕位置尽量稳定。展开属于主动阅读，应暂停外层自动追尾。
7. 仅在用户本来就在对话底部且未主动阅读历史时，外层对话才跟随新增内容。提供/复用回到底部入口恢复跟随。
8. 输出在用户已打开该工具且处于输出底部时才跟随流式内容；用户向上滚动或选择文本即暂停，回到底部再恢复。
9. 首次展开已有输出时从开头阅读，不强制跳到末尾；若输出继续流入，只有用户滚到输出底部后才启用追尾。
10. 输出拷贝、路径跳转、选中文字等操作不触发行/组展开收起。键盘及 VoiceOver 可识别展开状态，减少动态计时播报，支持减少动态效果设置。

## 取消普通工具组之外的第三层过程折叠

这是已确认的基础交互变化，属于本次最终实施范围。

普通对话时间线中，不再在完成时把已有工具组整体搬入一个新的「用时… → 执行过程」折叠容器。组本身已经负责收起执行细节，外层再折叠一次只会增加定位成本。整轮时长、文件变化等继续作为元信息/既有结果卡呈现；过程中的可见助手正文继续留在时序原位。

这样常规查看工具只需「打开组 → 打开工具」，完成时不会突然改变结构，也不会把用户手动展开的工具藏到第三层下面。代价是历史中的中间说明文字仍占空间，需要以真实长会话验证阅读密度。

实施时修改这次两端时间线的呈现策略，检查原生回退路径。`TurnDisplaySplit` 供其他调用方使用的能力以及分享、导出或独立历史阅读模式按各自用途保留。本次普通对话时间线的最终验收，不接受继续叠加整轮过程折叠的呈现。

## 组持续时长

组时长展示连续活动的墙钟时间：从第一条归属该组的活动开始，到组边界关闭且所属活动全部结束。包括组内 thinking、模型调用间隙和工具等待，不包含下一组或用户等待时间。

- 正在进行时每秒更新，结束后固定。
- 不把并行工具耗时相加：两个同时执行 10 秒的工具，组耗时约 10 秒，而不是 20 秒。
- `isCollecting` 表示仍接收活动，不代表某个工具正在运行；组边界已封闭但工具仍运行时，仍保持运行状态直到该组活动结束。
- 来源必须是可信的事件时间；历史回放不能以客户端重新收到事件的时间计算。第一步核实原始事件是否提供足够的工具/思考起止与边界时间，再决定仅扩充投影还是补充协议。
- 建议在活动投影保留 `startedAt`、`closedAt`、`finishedAt` 的必要时间事实，向 UI 提供明确的运行状态及 `durationMs`/计时起点。视图不自行推算组边界。
- 当前只有节点 timestamp 和工具 elapsedMs，`ToolGroup.Entry` 又丢弃了节点时间，不能据此宣称已具备可靠的历史组耗时。缺失真实时间的旧记录隐藏时长，禁止显示 0秒或重新计时。
- 整轮总时长仍属于整轮元信息，不与每个组的时长混用。

## 实施顺序与代码落点

### 第一批：先消除阅读障碍

1. Web `ToolGroupBlock` / `.tool-group-tools` 和 iOS `ToolCallGroupView`：移除组高度、组 ScrollView 与组级追尾，保留外层滚动和输出滚动。
2. iOS 改为组默认收起，与 Web 对齐；两端工具详情始终默认收起，保留用户选择。
3. 去掉普通组/工具类型图标，替换为组级运行指示；工具行保留明确异常文字。
4. Web `ToolResultCard` 与 iOS 工具详情：统一输入摘要、独立命令复制、独立输出框及空输出规则。继续保留结构化工具专用呈现与现有输出处理。
5. 同步调整完成后外层过程折叠，保证正在阅读的内容不会被完成事件隐藏。

### 第二批：统一两端的语义与状态

1. `ToolTranscriptPresenter`：提供统一当前动作、计数摘要、异常数、关键输入和详情元信息，避免 React 和 SwiftUI 各自拼文案。
2. `ConversationWebDocument` / Web `types.ts`：传递新增语义字段、复制命令 action，以及后续可靠时长；不要只在 CSS 中补假时长。
3. `TimelineProjection` / `ConversationTurn.ToolGroup`：只补必要的时间与呈现事实，保留既有身份、分组边界和到达顺序。
4. `TranscriptDocumentState` 与 Web disclosure context：隔离会话和轮次，保证展开状态不被生命周期覆盖。
5. 同步 `MacNativeChatTimeline` / `TranscriptDocument` 回退呈现、重复等待压缩及国际化文案，避免只优化桌面主路径。
6. Web 修改完成后按 AgentKit 构建流程重新生成捆绑的 ConversationWeb assets；不能只改生成 JS/CSS。

Talkify 是宿主，主要实现改动在相邻 `../AgentKit` 包。本批按上述交付顺序实施 macOS，工程验证和用户体验验收分别记录；macOS 工程测试通过不代表已获得用户对交互效果的最终验收，也不自动启动 iOS。

## 验收场景

- 单工具从开始到第二个工具追加，组身份与展开状态不变。
- 同一用户轮次跨三次模型调用仍按活动边界聚合；助手正文前后是两组，不吞正文。
- 运行组始终默认收起；用户展开后新工具追加不抢滚动、不展开输出。
- 组含 50–100 个工具时，列表完整进入对话布局，不出现组内滚动条；详情按需渲染，检查实际滚动性能后再决定虚拟化策略。
- 同时展开多个工具可以对照；长输出只在单工具输出框滚动，命令仍可见。
- 运行中无输出不占空框；完成无输出有明确文案；结构化结果不错误显示「无输出」。
- 一个工具失败、另一个仍执行时，组同时表达执行中和失败数。
- 执行完成时手动打开的工具保持可见，正文和结果不重排，阅读位置稳定。
- 已有输出首次展开从开头读；流式追尾、上滚暂停、文字选择暂停和回到底部恢复分别验证。
- 并行耗时不相加；历史回放不重新计时；没有可靠时间的旧组不显示虚构耗时。
- 相邻同任务等待压缩后，真实失败和原始记录仍可访问；两端呈现一致。
- iPhone 窄屏、大字号、深色、键盘和 VoiceOver，以及 macOS 触控板/滚轮与 Web 故障回退均可操作。

## 设计依据

Apple HIG 的 Scroll views 指出，同方向的嵌套滚动会造成难以控制的交互。本方案据此移除组级滚动，按本产品日志场景保留单工具长输出区，并要求真机验证页面与单工具输入/输出区之间的滚动交接。

参考：https://developer.apple.com/design/human-interface-guidelines/scroll-views

本方案已确认为本项目的实施基线。后续以长会话、多轮执行、失败与并行、手机阅读等真实记录检验交互质量，调整具体布局参数，并验证固定约束均已落实。

### macOS 编辑前自检

`preMutation` 保留原系统事件身份与完整文本，在连续活动组内以「编辑前自检」无图标单行展示，默认收起，用户可展开阅读。自检不再切断前后工具，不计入命令次数，单独计为「编辑前自检 N 次」。自检先到、后续工具再加入时保持组身份；真实正文和其他独立活动边界继续生效。iOS 暂时保留原系统消息展示。
